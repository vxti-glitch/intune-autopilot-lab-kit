          Deployment field guide · reviewed 2026-08-30
          
Choose the Windows Deployment Path

          
Classic Windows Autopilot and Windows Autopilot device preparation coexist. They use different registration, assignment, deployment-mode, application, script, and troubleshooting models; this lab never treats one as a rename of the other.

        

        

          
Classic Autopilot
User-driven deployment
Registered device, assigned classic profile, user credentials, Microsoft Entra join or supported hybrid path, MDM enrollment, ESP, apps and policy.

          
Classic Autopilot
Pre-provisioned deployment
Technician phase, scenario-specific attestation/physical-device requirements, reseal and user phase. Do not claim every Autopilot path requires TPM.

          
Classic Autopilot
Self-deploying / existing device
Separate supported scenarios with their own prerequisites; existing-device deployment can use Configuration Manager task-sequence media.

          
Device preparation
Windows Autopilot device preparation
Current Entra-join-first workflow with different group/policy behavior and supported limits. Standard preparation does not use the classic pre-registration/profile model.

Import specification
Manual Import CSV Specification and Validation Checklist
Exact case-sensitive headers: Device Serial Number, Windows Product ID, Hardware Hash, Group Tag, Assigned User. Serial and hash are required; the other three are optional. No extra columns, quotation marks, or more than 500 device rows. Export ANSI-compatible text and avoid editing the strict file in Excel. Source: Microsoft Learn, checked 2026-08-31.

          
Assignment boundary
Group Tags, Dynamic Device Groups, and Assignment Boundaries
Group Tag becomes the Autopilot device OrderID attribute. A dynamic Entra device group can evaluate that attribute, and Intune content can target the group. This offline demo validates only the expected mapping; it cannot verify membership or assignment.

          
Before OOBE
Pre-deployment Technician Readiness Checklist
Verify asset/serial, trusted hash source, selected path, supported Windows state, power, network, physical/TPM needs for that path, strict import data, reset approval, data disposition, and the endpoint-admin handoff.

          
After enrollment
Post-enrollment Validation Checklist
Verify join and MDM state, primary-user/ownership expectation, sync, required apps, configuration and compliance results, update state, BitLocker/recovery-key ownership, user task, and ticket evidence. Tenant results require authorized access.

          
Evidence collection
Autopilot and Enrollment Evidence Collection Guide
Record OOBE stage/error/time, dsregcmd /status, mdmdiagnosticstool.exe -area Autopilot -cab ..., DeviceManagement and Autopilot Event Viewer channels, MDM diagnostic report, and IME logs under ProgramData\Microsoft\IntuneManagementExtension\Logs. Redact identifiers and tokens.

          
ESP decision flow
Enrollment Status Page Troubleshooting Flow
Identify device preparation, device setup, or account setup. Determine the blocking item, then separate network, certificate, policy, app detection/install context, IME, timeout, or service-side assignment. Export the stage, item, code, timestamp, logs and attempted safe action.

        


        
Troubleshooting library
Deployment scenarios
Every scenario separates local evidence from tenant evidence and ends with a bounded conclusion, safe handoff, verification, and escalation condition.

        

          
01
Hardware Hash Import Is Rejected
Check header case/order, required serial/hash, supported optional columns, extra fields, quotes, encoding, duplicate identity, 500-row limit, and the exact portal error.

          
02
Device Is Not Recognized as an Autopilot Device
Compare trusted registration source, serial, import status, service timing, selected deployment path, reset/OOBE state, and authorized admin evidence.

          
03
Expected Deployment Profile Does Not Apply
Trace device identity → Group Tag/OrderID → dynamic group → Intune assignment → profile status and propagation. Only the first mapping can be checked offline.

          
04
Required Win32 App Blocks Enrollment Status Page
Capture ESP item/status and IME, AppWorkload, and AppActionProcessor logs; examine detection, requirement, install context, return code, content/network, and retry behavior.

          
05
Device Joins Microsoft Entra ID but Does Not Enroll in Intune
Check MDM scope/license, user/device limit, enrollment restrictions, network, local scheduled/event evidence, and device state. Tenant causes require an authorized admin.

          
06
User Receives an Unexpected OOBE Experience
Separate consumer/setup screens, an unrecognized classic device, wrong path/profile, network failure, previous device state, and unsupported Windows edition/build.

          
07
Device Enrolls with Incorrect Apps or Policies
Compare user/device targeting, dynamic membership, assignment filters, intent, conflicts, sync/check-in, and expected versus observed results.

          
08
Network Restrictions Interrupt Enrollment
Capture stage, DNS, time, proxy, TLS and required Microsoft endpoint reachability. Link to Microsoft’s maintained endpoint list instead of copying a stale allowlist.

          
09
TPM or Firmware Blocks a Scenario That Requires Attestation
Verify physical/VM context, selected scenario, TPM version/state, firmware and current requirement. Escalate OEM/security ownership; do not generalize to every path.

          
10
Enrollment Limit or Restriction Blocks the User
Record error/time, platform/ownership context, user device count, restriction/limit evidence, and the authorized Intune path for review.

          
11
Enrollment Completes but Compliance Remains Unknown
Separate sync/check-in, policy assignment, evaluation prerequisites, grace period and Conditional Access impact.

          
12
Authorized Reset and Redeployment Handoff
Simulate approval, data disposition, reset/deregister/reuse decision, ownership, execution evidence, and post-enrollment verification. No real device action is exposed.

        


        

          
Autopilot, Entra, Intune, and OOBE Log Reference
DeviceManagement-Enterprise-Diagnostics-Provider; ModernDeployment-Diagnostics-Provider-Autopilot; Provisioning-Diagnostics-Provider; MDM diagnostics CAB/report; and Intune Management Extension logs. Match the log to the failing stage.

          
Intune Network Dependencies for Windows Enrollment
Validate DNS, time, proxy and TCP 80/443, then link Microsoft’s maintained Intune endpoint list. Do not publish a copied endpoint inventory that will age.

          
Reset, Reuse, Deregistration, and Redeployment Decision Guide
Choose only with ownership, authorization and data-risk review. Wipe, reset, Autopilot Reset, deregistration and reimport solve different problems and require tenant/device roles.

          
Post-enrollment Policy Baseline Map
Concept map only: configuration, compliance, update, security and app policies can target user/device groups with filters. This lab does not invent production settings.
